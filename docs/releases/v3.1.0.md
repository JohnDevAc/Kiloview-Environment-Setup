# Environment Setup 3.1.0

Environment Setup now supports the Toolbox lifecycle interface for correlated
installation, update, repair, inspection, removal and recovery. Progress and
terminal results distinguish completion, cancellation, partial changes, restart
and blocked recovery; retry preserves the selected Client or Server role.

## Changes

- Current or newer NDI Tools with the required applications skips the payload
  download and installation. Explicit repair and missing applications still
  trigger repair. Vendor metadata lookup is bounded and reports progress.
- Client setup uses the PC Agent's verified package and lifecycle interface.
  Installed, configured, onboarded and healthy remain separate states.
- WSL bootstrap, console ownership, readiness deadlines and restart continuation
  retain durable evidence when work is interrupted. Concurrent diagnostic readers
  do not prevent normal journal updates.
- Server removal stops its watchdog and retains an inactive environment/data by
  default. Permanent deletion requires an available purge choice and fresh
  consent. Client removal retains shared NDI Tools and PC Agent.
- The wizard removes the Save diagnostics and Licences buttons and the automatic
  diagnostics text line. Diagnostic files and review-stage licence delivery remain.

## Release channels and deployment

Stable is `v3.1.0` on `main`; development is `v3.1.0-dev.1` on `dev`. Both contain
the same runtime implementation. `version.json` records the numeric build version,
release identity and channel. Windows assembly/file and MSI versions stay numeric;
ProductVersion, engine identity and lifecycle requested-version validation retain
the development suffix so the updater can distinguish channels.

The published setup EXE includes its Windows package. The lifecycle ZIP contains
that EXE, its SHA-256 sidecar and `toolbox-lifecycle.json`; it is the Toolbox package.
Build and validation instructions are in [LIFECYCLE.md](../LIFECYCLE.md). The CI
workflow validates and uploads build artifacts; release publication is separate.

An app-only deployment uses the verified inner Burn package built under
`artifacts/package`, with `/repair /quiet /norestart /log <path>`. Its MSI owns the
configuration application and shortcut. Do not launch a Server setup/update or
runtime-maintenance operation merely to upgrade the configuration application.
Verify the installed application and engine against the release payload, then
inspect lifecycle state and confirm existing roles, data and shared products.

## Validation scope

The accepted implementation passed 340 isolated checks plus package, licence,
checksum and native vendor-process isolation checks. Windows 11 VM acceptance
covered fresh Client/Server installation, actual update/repair flows, restart
continuation, preserving role removal, explicit purge followed by fresh Server
installation, and compatibility with the Job Configurator and PC Agent. The
current NDI Tools download skip was observed with NDI Tools 6.3.2. Server HTTP
access was verified locally and from another computer on the LAN.

Release preparation adds stable/development metadata validation and reruns the
checks against each channel. Physical device streaming, GPU behavior, fresh
pre-login behavior and every possible fault/recovery combination are not claimed
by the VM evidence. Reuse of a prepared NDI installer download across a reboot
remains deferred; this is separate from skipping an already-current installation.
