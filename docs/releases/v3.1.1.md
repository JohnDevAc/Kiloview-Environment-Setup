# Environment Setup 3.1.1

Fresh Server setup now allows enough time for Ubuntu's first package-index
refresh, checks available Windows storage before provisioning, and handles
WSL's informational help exit correctly.

## Changes

- Linux source readiness retains complete APT output and identifies the failed
  stage. Metadata refresh has a four-minute deadline plus termination grace,
  while strict source-error checks remain enabled. Timeout and source failure
  produce distinct diagnostics before Docker or application installation.
- Server setup, repair, update, resume and runtime maintenance check available
  host storage on the actual distro, Windows/NDI and download/state volumes.
  The reserve is 16 GiB for distro growth, 2 GiB for Windows/NDI and 2 GiB for
  staging, normally 20 GiB when they share a volume. It is a safety reserve,
  not a guarantee of total installation, backup or application-data size.
- Low space stops before component changes and reports the volume and space
  to free. Client setup, inspection, verification and removal do not require
  the Server installation reserve.
- New managed distributions use an explicit, unique storage location. Existing
  and moved distributions retain their registered paths; orphaned folders are
  never adopted or deleted. WSL help exits zero and minus one are accepted only
  when the install-location option is actually advertised. Genuine CLI errors,
  timeouts and result-persistence failures remain failures.

## Channels and packages

Stable is `v3.1.1` on `main`; development is `v3.1.1-dev.1` on `dev`. Runtime
implementation is shared; release identity and channel metadata remain separate.
Windows assembly/file and MSI versions are numeric `3.1.1`; product and engine
identities retain the development suffix for lifecycle version validation.

The full setup EXE contains its Windows package. The lifecycle ZIP contains
that EXE, its SHA-256 sidecar and `toolbox-lifecycle.json`. The CI workflow builds
and validates the package; publication is a separate operation. Existing releases
remain available for rollback. See [LIFECYCLE.md](../LIFECYCLE.md) for build checks.

## Validation scope

The underlying implementation passed isolated installer, storage, native WSL,
Linux-source and lifecycle regressions. A disposable Windows 11 VM verified the
actual low-space guard, then fresh Ubuntu, Docker, KiloLink and NDI Server roles
with no manual rescue. Setup exited zero. Discovery and local/LAN HTTP health
recovered after reboot without manual service starts.

That VM used an unpublished portable owner build over an existing configuration
MSI. Full-package checks verified MSI contents, embedded payloads, licences,
checksums and private-desktop vendor-process isolation. They do not establish
an actual 3.1.1 MSI upgrade or public-feed installation; neither is claimed here.
Physical streaming and every hardware or recovery scenario remain outside this
validation. The startup task was running with healthy services after reboot,
but its historical nonzero task-result value was retained as unresolved evidence.

A successful private QA operation does not erase a different failed operation
in Toolkit's history. No operation records were changed merely to remove that
historical warning.
