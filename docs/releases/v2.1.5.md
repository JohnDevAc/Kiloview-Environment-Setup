# Kiloview Environment Setup 2.1.5

NDI Tools updates and repairs now check for applications using installed NDI files before starting a replacement. A blocked operation names the applications to close so setup can be retried. This addresses a reproduced silent-installer failure where a background NDI application held a codec DLL and the vendor installer aborted and rolled back Tools.

- Rechecks file usage after preparing a package and before installation.
- Keeps vendor setup from automatically closing other applications and records a separate NDI installer log whose path is included in failures.
- Resumes the remaining server configuration after sign-in when NDI requires a Windows restart.
- Retains the current-version download check: healthy current or newer NDI Tools installations skip the server update download.

Validation: 128 Windows PowerShell 5.1 regression checks and the native installer fixture passed, including real read-only file-lock detection. The official NDI installation failure was reproduced and the installation repaired after temporarily stopping the identified background task, which was restored afterward. Live Repair and Update commands using the packaged engine both completed successfully; KiloLink returned HTTP 200 and NDI Discovery was listening. Saved server and NDI settings were retained and no Windows reboot was needed. GUI startup was checked; the live maintenance runs used the supported installer commands.
