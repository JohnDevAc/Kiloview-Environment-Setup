# Kiloview Environment Setup 2.1.4

Server updates now check the version advertised on NDI's official Tools download page before downloading the installer. A current or newer installed version with Discovery Service present skips the full download. Older versions and missing Discovery files still use the signed installer; unavailable or ambiguous version information falls back to downloading and verifying the package. The preflight result is used for the current operation, and subsequent updates check again.

The setup window now has fewer controls: the Save diagnostics and Licences buttons have been removed from every page, along with the "Diagnostics are saved automatically" line. Navigation and completion buttons fit the remaining space.

Diagnostic logs continue to be written to `C:\ProgramData\KiloLink\setup-launcher.log`. Vendor licence links and acceptance remain available on the review page, and the installer still includes the MIT licence and third-party notices.

Validation: all 117 isolated Windows PowerShell 5.1 regression checks pass, covering version metadata, current/newer/older installations, preflight reuse, repair, offline packages and signature validation, plus native page layout across display scales and constrained desktops. A read-only check against the live official download page confirmed that a simulated current installation completes both NDI update phases without downloading an installer. Rendered role-selection, server-maintenance and completion screens were visually checked. No production installation, network change or Windows reboot was performed during validation.
